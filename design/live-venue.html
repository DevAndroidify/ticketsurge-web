What happens when 1,200 people want 384 seats at the same second?

I built TicketSurge to find out. The buyers here are bots, but the Redis scripts, the database rules and the Kafka consumers they hit are the real ones from the backend.

How it works, briefly

1 Redis keeps the line fair. Everyone joins one queue and gets let in in batches. Push too hard and you get a 429 and a short timeout. Redis 2 One click wins each seat. A Lua script checks and claims a seat in a single step, so when six people click it, five get a 409. PostgreSQL has a unique index as a second line of defence. Redis, PostgreSQL 3 The slow stuff happens later. Payment, tickets and emails go through Kafka, so the booking returns straight away. Kafka

What it doesn't do

  • Take real money. Payments are simulated.
  • Need a server to try. In simulated mode, everything runs in this tab.
  • Pretend the bots are people. They're scripts, but they use the same API you do.
